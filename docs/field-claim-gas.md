# 外場專員作業系統（GAS）功能盤點與整合規格

來源：台北／台中兩份「檸檬專員作業系統 v2.6.0」Apps Script 專案，各含三個檔案：

| 檔案 | 角色 | 台北 | 台中 |
|---|---|---|---|
| `Code.gs`（模組一～九） | Web App 後端：寫入回報／收現／請款工作表、登入、查詢 | ✅ | ✅（改名、車馬費簡化） |
| `Index.html` | 專員用手機表單（google.script.run 呼叫後端） | ✅ | ✅ |
| 請款設定 `.gs`（onOpen 選單） | 行政在「專員請款」工作表手動批次補欄位 | ✅ | ✅（少一個選單項） |

整合目標：把**行政批次功能（請款設定選單）**移植到 `tools/field_management/`，由 `toolapp.py`「外場排程系統」直接執行（做法同 `roster_raise.py`、`finance_management/deposit_report.py`）。
專員填表的 Web App 依賴 `doGet` / `google.script.run`，建議**維持在 GAS**，只修正下面列出的錯誤。

## 2. Web App（Code.gs + Index.html）

### 2.1 專員端功能
- **登入**：專員姓名 + 身分證字號（`專員個人資料` 的「專員姓名」「身分證字號」）。可勾選在瀏覽器記住姓名／身分證（只顯示前 3 後 3 碼）。登入後自動帶入三張表單的專員姓名，並在背景查近 3 日記錄。
- **案場回報**：工作項目回報／下次預約需求／兩者，依類別顯示區塊。
- **收現及加/減時**：加減時、收現金、兩者；「加減時 + 一般客加時」會帶出收現區塊。
- **請款申請**：9 種請款項目，依項目顯示對應欄位；台北的跨區車馬費會依 `CROSS_ZONE_MAPPING` 篩選可選的結束區域並當場檢查是否符合跨區。
- **查詢記錄**：依服務日期區間＋表單類型查詢自己的資料，可開「檢視詳細」彈窗或「檢視提交頁」唯讀頁。
- 驗證：顧客電話（含第二位顧客）必須 10 位數字；前後端各驗一次。

### 2.2 寫入流程
`submitFormData` → `prepareFormData` → `validateForm` → `writeDataToSheet`：缺的表頭自動補在最後 → 依表頭組一列寫到最後一列下方 → A 欄寫提交ID。台北版另外套用列高規則（收現／請款固定 21；回報 H～J 換行並自動撐高）。

### 2.3 規範補貼（AM 欄）
| 請款項目（主管專用看子項目） | 台北 | 台中 |
|---|---|---|
| 跨區車馬費／車馬費 | 200 | 100 |
| 現場收取車馬費、大型器材車馬費 | 100 | 100 |
| 客戶取消車馬費、主管-取消車馬費 | 前一天 100；其他 200 × 取消時數 | 同左 |
| 病假代班費、延長服務代班費 | 300 | 300 |
| 客訴補做 | `時薪 × N小時` 文字 | 同左 |
| 工具組運費 | 150 | 150 |
| 推薦獎金 | `依公司規定` | 同左 |

## 3. 請款設定選單（行政批次，主要移植對象）

都作用在**目前作用中的工作表**，輸入列範圍 `起:迄`（例 `2:50`）。

| 選單 | 功能 | 台北 | 台中 |
|---|---|---|---|
| 🚀 批次設定AD/AE/AF/AG/AJ欄 | 可勾選欄位一次重算 | ✅ | ✅ |
| 🔑 設定Google Maps API金鑰 | 驗證後存 Script Property `GOOGLE_MAPS_API_KEY`（目前沒有功能真的用到） | ✅ | ✅ |
| 📍 只產生AG欄Google Map連結 | 只重算 AG | ✅ | ✅ |
| 🔍 檢查專員資料對照 | 顯示對照表欄位與前 5 筆 | ✅ | ✅ |
| 🚗 批次產生AF/AG欄（跨區專用） | 只處理 G 欄含「跨區」或「車馬」的列 | ✅ | — |

### 批次設定各欄規則
- **AD 顧客地址1**：用 `D|E|F`（服務日期｜顧客姓名｜顧客電話）去對照「專員個人資料」的 `服務日期|客戶姓名|聯絡電話` → 取「客戶地址」。
  找不到時依序退而求其次：日期+姓名 → 日期+電話後 4 碼 → **只比日期**；全部找不到就寫 `D E F` 合併文字。
- **AE 顧客地址2**：同上，但用 `D|O|P`；O、P 都空就清空 AE。
- **AF 實際跨區1**：依 N 欄決定起訖，取地址去空白後前 6 字，格式 `起-訖`。
  家到案場 AC→AD；案場到家 AD→AC；案場到案場 AD→AE。
- **AG 實際跨區2**：同上起訖組 `https://www.google.com/maps/dir/起/訖`；缺資料寫 `❌ 缺少跨區類型`／`❌ 地址不完整`，起訖相同寫 `📍 起點終點相同`。
- **AJ 給付期別**：輸入值（例 `202601-1`）寫入範圍內每一列。

## 4. 本次修改需求

   - 外場排程系統批次執行時：範圍內車馬費＋案場到案場的列一律重算 AN；其他列只補空白的 AN。
   - 專員送出表單時（GAS Web App）：見下方 GAS 修改。
2. **選定列範圍執行時一律寫入 AJ 期別**：批次執行必填期別（格式 `YYYYMM-期數`），範圍內有資料的列都寫入 AJ；空白列不動。

### GAS Web App 對應修改（Code.gs，台北／台中都要改）

`Utilities.generateClaimRemark` 改成多收跨區類型與第二位顧客：

```javascript
generateClaimRemark(serviceDate, customerName, claimType, supervisorItem, zoneType, secondCustomerName) {
  const parts = [];
  if (serviceDate) {
    const date = new Date(serviceDate.replace(/-/g, '/'));
    if (!isNaN(date.getTime())) {
      parts.push(`${String(date.getMonth() + 1).padStart(2, '0')}/${String(date.getDate()).padStart(2, '0')}`);
    }
  }
  const isSiteToSite = (claimType === '跨區車馬費' || claimType === '車馬費') && zoneType === '案場到案場' && secondCustomerName;
  if (isSiteToSite) {
    parts.push(customerName ? `${customerName}-${secondCustomerName}` : secondCustomerName);
  } else if (customerName) {
    parts.push(customerName);
  }
  const item = (claimType === '主管專用' && supervisorItem) ? supervisorItem : (claimType || '');
  if (item) parts.push(item);
  return parts.length ? parts.join('') + '-' : '';
},
```

`mapClaimFields` 呼叫處加上兩個參數：

```javascript
const claimRemark = Utilities.generateClaimRemark(
  formData.serviceDate, formData.customerName, claimType, formData.supervisorItem,
  formData.zoneType, formData.secondCustomerName
);
```

## 5. 現有程式的問題（移植時一併修正）

| # | 問題 | 影響 |
|---|---|---|
| 1 | 台北 `mapClaimFields` 呼叫不存在的 `this.calculateAutoFieldsWithoutCrossZone(...)` | **台北請款每一筆送出都會失敗**（TypeError）。應改回 `calculateAutoFields`。 |
| 2 | 台北 `mapClaimFields` 裡面多貼了一段 `batchRecalculateCrossZoneIfEmpty()`，還把「檢查跨區」值寫到 AF/AG（應為 AH/AI） | 死碼，也容易誤用，刪除。 |
| 3 | `const Utilities = {...}` 蓋掉 GAS 內建 `Utilities` | `Utilities.formatDate(date,'yyyyMMdd')` 變成呼叫自訂函式，提交ID 的日期段會是「2026/10/16 上午…」；若批次選單和 Web App 在同一專案，`Utilities.sleep()` 會丟錯，**第 10、20、30… 列被寫成「❌ 處理錯誤」**。應改名（如 `AppUtils`）。 |
| 4 | AD/AE 的「只比日期」退路 | 對不到人時會隨便抓到同日期別的顧客地址，AF/AG/車馬費審核會錯。建議拿掉這一層，找不到就標示。 |
| 5 | `專員個人資料` 同時被當登入表（專員姓名/身分證/地址）與客戶地址對照表（服務日期/客戶姓名/聯絡電話/客戶地址） | 兩種表頭須同時存在才能都正常；移植時把對照來源改成可設定（例如外場訂單資料）。 |
| 6 | 自動填入時查顧客地址的工作表 `顧客資料`/`客戶資料`/`客戶清單` 實際不存在 | Web App 寫入的 AD/AE 永遠是空的，只能靠批次補。 |
| 7 | 選單說明把 E/F 寫成「時間／時數」，實際是顧客姓名／電話 | 文字修正。 |
| 8 | 台中 `calculateStandardSubsidy` 有重複的 `case '車馬費'` | 無實際影響，整理掉。 |
| 9 | 批次逐格 `getRange().getValue()/setValue()` | 列數多時很慢、容易逾時；移植後改整段讀寫。 |
| 10 | 前端登入時 `!passwordField.dataset.isMasked` 永遠為 false | 前端格式檢查失效（後端仍有檢查）。 |

## 6. 整合到外場排程系統（已完成）

- 程式：`tools/field_management/staff_claim.py`，測試：`tests/test_staff_claim.py`。
- 試算表位置：主控試算表「財務帳務設定」登記表中 `清潔異動設定／台北`、`清潔異動設定／台中` 的試算表ID
  （即「2026台北內勤工作表單」「2026台中內勤工作表單」），請款分頁用「專員請款」的 GID 定位（台北 279541195、台中 749987965，見 `CLAIM_SHEET_GIDS`），地址對照用同一份試算表的 `專員個人資料`。
- `toolapp.py` →「外場排程系統」新增兩個功能（地區：台北／台中）：
  - **【請款】批次設定請款欄位**：輸入起始列、結束列、給付期別 → 寫 AD/AE/AF/AG/AJ/AN。
    AD/AE 對照「專員個人資料」G 服務日期＋L 客戶姓名＋N 聯絡電話 → M 客戶地址（依表頭名稱定位）；
    比對順序：日期＋姓名＋電話 → 日期＋姓名 → 日期＋電話，查不到保留原值並在日誌列出列號。電話比對會忽略開頭 0。
  - **問題標記**：批次執行時，範圍內有問題的格子依類型上底色，原因寫在備註（以 ⚠️ 開頭）：
    | 底色 | 問題 | 欄位 |
    |---|---|---|
    | 淡紅 `#F4CCCC` | 地址少字或格式不完整（不是「縣市＋區」開頭，例如「台北中正區…」、「2026/05/04 王小明 0912…」） | AC/AD/AE |
    | 淡紫 `#D9D2E9` | 查無地址（有跨區類型但用得到的地址空白） | AC/AD/AE |
    | 淡橘 `#FCE5CD` | 無法產生地圖連結（❌ 地址不完整／未知跨區類型、📍 起點終點相同） | AG |
    | 淡黃 `#FFF2CC` | 案場到案場的第二位顧客與顧客相同 | AN |
    下次執行時，已修正的格子會清掉底色與備註；只清備註以 ⚠️ 開頭的格子，人工上的底色、備註不會動。
  - **【請款】檢查地址對照**：只讀，顯示兩張表的欄位位置與有效地址筆數。
- 不移植：Google Maps API 金鑰（沒有功能使用）、「只產生AG欄」（批次功能已包含）、「跨區專用AF/AG」（AF/AG 只在 N 欄有值時重算）。
