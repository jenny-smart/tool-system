# VIP 排程差異比對

先匯出 VIP 日曆，再執行「【儲值】建立VIP排程工作表」。預設會比對並安全更新；勾選「只比對差異，不更新排程工作表」時，只寫入差異表，排程內容及底色不變。

| 情況 | 更新方式 | 底色 |
| --- | --- | --- |
| 新事件、新客戶 | 加在原工作表末尾；依既有狀態規則決定是否可建單 | 淡黃 |
| 未成單事件異動 | 更新 A:I，保留 J:AD 的購買項目、結果、原因及其他作業資料 | 淡黃 |
| 已有 M 欄單號的事件異動 | 保留原 A:AD，只記錄日曆的新值供人工核對 | 橘色 |
| 無法唯一比對或已有成單客戶新增不同事件 | 不加入新的待成單列，保留原資料供人工核對 | 橘色 |
| 本次匯出未見的原列 | 不刪除；沒有單號且仍為未安排時改為待確認 | 淡紅 |
| 同一事件已在其他月份工作表 | 只在差異表記錄跨月異動，不新增可能重複的排程 | 差異表 |

既有列不排序、不清空，以保留原列號。差異主要比對 A:I；既有 J 與 K:AG（以及右側自訂欄位）資料保留。追蹤欄「日曆事件ID／日曆異動／日曆異動內容」依欄名重用；缺少時新增到所有既有資料右側，空白標題下有資料的欄位也不覆蓋。已成單列保留 A:AD，只記錄異動供人工核對。

「排程差異_台北202611」等工作表記錄時間、列號、原單號、原值與日曆新值、處理方式；相同未解決差異不重複新增。只比對與實際更新分開記錄。標色及異動備註會保留，便於回查。

新匯出會保存 Google Calendar 事件 ID，因此人數、日期、時數或地址變更後仍可追蹤同一事件。舊排程尚無事件 ID 時，先按姓名、電話、地址、日期及時段比對，再僅使用唯一的客戶對應；無法唯一判斷時交給人工核對。

匯出會記錄實際日期範圍。部分日期匯出不會將範圍外列標示為日曆未見；「本次未見」不等同已確認取消。空白月份也會刷新日曆快照，不沿用舊日曆資料。

已成單異動不會自動取消、改單或重新成單。請先確認後台原單，處理完成後再依實際訂單更新工作表；不要為了重跑直接清空原單號。尚未成單的失敗列仍保留 N 欄結果，不會因此自動重試。

CLI 只比對：

```sh
python -m tools.service_management.stored_value --step 3 --area 台北 --start 2026-11-01 --end 2026-11-30 --compare-only
```
