# VIP 排程差異比對

先匯出 VIP 日曆，再執行「【儲值】建立VIP排程工作表」。網站一律比對並安全更新 A:J、標色，保留既有 K:AG；不再提供只比對勾選項。

| 情況 | 更新方式 | 底色 |
| --- | --- | --- |
| 新事件、新客戶 | 加在原工作表末尾；依既有狀態規則決定是否可建單 | 淡黃 |
| 第一次建立（工作表不存在或為空白） | 視為基準，整批寫入；不標「新增」、不記差異表 | 不標色 |
| 未成單事件異動 | 更新 A:J，保留 K:AG 的結果、原因及其他作業資料 | 淡黃 |
| 已有 M 欄單號的事件異動 | 更新 A:J，保留 K:AG 原單號及作業結果；記錄前後差異供確認後台訂單 | 橘色 |
| 同一客戶多筆未成單列對應到不同日期的新事件（例如每月確認改成已確認） | 依日期、時段先後一對一更新該列 A:J，每列只記自己的異動 | 淡黃 |
| 無法唯一比對，且該客戶有已成單列；或已有成單客戶新增不同事件 | 不加入新的待成單列，保留原資料供人工核對 | 橘色 |
| 本次匯出未見的原列 | 不刪除；沒有單號且仍為未安排時改為待確認 | 淡紅 |
| 同一事件已在其他月份工作表 | 只在差異表記錄跨月異動，不新增可能重複的排程 | 差異表 |

既有列不排序、不清空，以保留原列號。差異主要比對 A:I；既有 K:AG（以及右側自訂欄位）資料保留；J 保留原值或公式，地址異動時更新上月查詢公式。追蹤欄「日曆事件ID／日曆異動／日曆異動內容」依欄名重用；缺少時新增到所有既有資料右側，空白標題下有資料的欄位也不覆蓋。已有訂單編號的列也更新 A:J，保留 K:AG 的訂單編號與作業結果；後台訂單需另行人工確認是否異動。

「排程差異_台北202611」等工作表記錄時間、列號、原單號、原值與日曆新值、處理方式；相同未解決差異不重複新增。命令列預覽與實際更新分開記錄。標色及異動備註會保留，便於回查。

新匯出會保存 Google Calendar 事件 ID，因此人數、日期、時數或地址變更後仍可追蹤同一事件。舊排程尚無事件 ID 時，先按姓名、電話、地址、日期及時段比對，再僅使用唯一的客戶對應；無法唯一判斷時交給人工核對。

匯出會記錄實際日期範圍。部分日期匯出不會將範圍外列標示為日曆未見；「本次未見」不等同已確認取消。空白月份也會刷新日曆快照，不沿用舊日曆資料。

已成單異動不會自動取消、改單或重新成單。請先確認後台原單，處理完成後再依實際訂單更新工作表；不要為了重跑直接清空原單號。尚未成單的失敗列仍保留 N 欄結果，不會因此自動重試。

CLI 只比對：

```sh
python -m tools.service_management.stored_value --step 3 --area 台北 --start 2026-11-01 --end 2026-11-30 --compare-only
```

異動類型、異動內容與「更新日期」（台北時間）直接寫在原排程工作表 AG 右側的追蹤欄，右側已有資料時繼續向右新增，不覆蓋既有欄位。相同結果重跑不刷新更新日期。原 AE:AG 事件追蹤資訊會讀取並遷移到右側；差異表僅保留歷史紀錄。

事件 ID 改變時，若客戶、電話、地址與日期能唯一對應，仍視為同一排程，比對實際人數、備註、日期與時段等異動。成單寫回的「已安排」對上日曆「未安排」不列為服務異動；暫停、待確認與真正時段變更仍須核對。

同一天另有暫停事件時，保留獨立暫停列，不因同客戶已有成單而將原有多筆訂單標成需核對；暫停列維持暫停狀態。舊版匯出以姓名、地址、日期去重曾漏掉同日第二筆，現依事件 ID 分列。

網站移除「只比對差異，不更新排程工作表」，一律安全更新：唯一對應的日曆異動直接更新 A:J 並標色，既有 K:AG 及右側自訂資料保留。J 的既有值／公式一般保留，地址變更時恢復同區上月 xlookup 公式。訂單已安排對上日曆未安排時保留已安排；暫停與其他實際狀態異動仍更新。異動前後差異與更新時間記錄在 AG 右側，已有單號不清除、不自動重新成單。命令列 compare-only 僅保留給技術人員預覽使用。

新增「【儲值】全跑（抓儲值金＋匯出VIP＋建立排程工作表）」：依序執行三步，使用同一地區、期別／日期範圍。前置步驟失敗或有啟用地區缺少日曆 ID 時不建立排程，以免使用舊資料。原兩步全跑仍保留。CLI：`python -m tools.service_management.stored_value --step 4 --area 台北 --start 2026-11-01 --end 2026-11-30`。

建立排程時，同姓名、地址、日期有多筆資料（包含暫停）會將整組標為淡紫色。比對使用正規化姓名、地址與日期，原訂單與狀態不變；淡紫色優先於一般異動底色。

同日多筆淡紫色標示也套用於「匯出VIP日曆」的定期VIP表，以及單獨建立排程、兩步全跑、三步全跑。日曆匯出刷新時先清除舊底色，再標示目前的同日多筆群組。

同日多筆可能是週期中的單次人數／時數異動，淡紫色提醒核對有效列，並不代表需要建立多張訂單。保留原列、異動列與暫停狀態，不自動合併或刪除。

建立排程時，原因為「系統未產生新訂單編號」、M 單號空白且對應定期VIP Q 欄差額 > 0，整列標淡紅色，優先於同日多筆淡紫色。Q 只顯示於客戶首列時，同姓名、電話其他日曆事件沿用該月 Q；0、負數、不合法數值不標色。不修改原因、結果或單號，不自動重試成單。

## 排程預約條件（暫時性，例如年節大掃除）

在客服排程系統選「【儲值】建立VIP排程工作表」或「【儲值】全跑（抓儲值金＋匯出VIP＋建立排程工作表）」時，匯出設定下方有「排程預約條件」區塊：

- **是否套用**：勾選「套用預約條件」。匯出範圍與「【大掃除】年度設定」的大掃除期間重疊時預設勾選，其他時候預設不勾，可手動改。
- **期間**：跟著畫面的匯出起迄日，不另外設定（客人可能改到年後，日曆匯出到 2 月底即可涵蓋）。
- **確認來源與欄位**：在畫面填寫，執行時存到主控試算表「排程預約條件」（每個地區一列），下次自動帶入；欄位標題有滑鼠提示。

| 畫面欄位 | 說明 | 範例 |
| --- | --- | --- |
| 確認檔案／確認工作表 | 確認表的試算表 ID 或網址、工作表名稱 | 2026台北內勤工作表單／2026大掃除 |
| 回覆確認欄／確認值 | 值符合才算已回覆確認，可填多個（逗號分隔） | V／TRUE |
| 備註欄 | 帶入排程「確認備註」欄供參考 | W |
| 改加：排程欄／關鍵字 | 排程此欄含關鍵字＝改加（A 欄＝日曆標題第一個《》內容） | A／改,加 |
| 已確認：排程欄／關鍵字 | 排程此欄含關鍵字＝已確認（B 欄＝日曆標題 <> 備註） | B／已確認 |
| 進階：姓名／電話／地址欄 | 確認表中比對客戶用的欄位 | C／D／F |
| 進階：確認表改加欄 | 選填；確認表此欄含關鍵字也算改加 | （空白） |

期間內的未成單列，在 AG 右側寫五欄（純文字）：

| 欄位 | 內容 |
| --- | --- |
| 回覆確認 | 確認表 V 欄的值（TRUE／FALSE／空白）；找不到客人寫「查無」 |
| 確認備註 | 確認表 W 欄的值 |
| 改加標記 | 排程 A 欄含的改／加 |
| 已確認 | 排程 B 欄含「已確認」（原本每月確認、改成已確認） |
| 預約條件 | 依序判斷：改加 → 已確認 → 可約（回覆確認為 TRUE）→ 未回覆 |

- 狀態欄不改。orders-system 三種批次成單畫面可勾選「本次預約對象」（預設只有可約），依序約：可約 → 改加 → 已確認 → review 未回覆。
- 個別客人要例外處理時，可直接改該列「預約條件」；下次更新排程會依規則重新判斷。
- 不勾「套用預約條件」再更新排程，五欄會清空。已有訂單編號的列五欄留空。期間外、或沒有啟用規則時完全不影響，也不會新增這些欄。
- 確認表讀不到時整次更新失敗，不會誤約。
- 日曆標題只取第一個《》作為 A 欄：請寫成《改》或《3人4小時改》，不要寫《3人4小時》《改》。
- 先前版本的「確認狀態」欄會自動改名為「回覆確認」沿用。
