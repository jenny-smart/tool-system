# 內勤薪資管理（staff_payroll）

新增於 `jenny-smart/tool-system`，路徑：`tools/staff_payroll/`

## 根目錄結構

```
根目錄（Drive Folder，1LYmhOIcgjmO5-74zh1D1pKfVizIF5Wls）
└── YYYY薪資
    ├── 台北（資料夾）
    │   ├── YYYY台北薪資單總表（Google Sheet）
    │   │   ├── 員工個資（工作表）
    │   │   └── 薪資單（工作表，AA1:AH15 為單人薪資單樣板，AC2 = 姓名；
    │   │       同一份工作表另外有一個 A/D/AH 三欄的月份×員工金額紀錄表，見下方說明）
    │   ├── YYYY桃園薪資單總表（Google Sheet，實際上也收在台北資料夾底下，不是桃園自己的資料夾）
    │   ├── YYYY元大帳戶-台北（Google Sheet）
    │   └── YYYY元大帳戶-桃園（Google Sheet，同樣收在台北資料夾底下）
    ├── 台北》薪資單（資料夾，存放台北產出的 PDF）
    └── 桃園》薪資單（資料夾，存放桃園產出的 PDF，這個子資料夾仍在各自地區資料夾底下）
根目錄
└── YYYY薪資
    └── YYYY內勤薪資名冊（Google Sheet，內含各月 mail 分頁）
```

**2026-08-20 確認的關鍵結構事實：** 所有地區的「YYYY地區薪資單總表」（以及看起來「YYYY元大帳戶-地區」也是）實際上都收在同一個「台北」資料夾底下，不是各自的地區資料夾。各地區自己專屬的東西目前只剩「薪資單」PDF 輸出資料夾還在各自地區資料夾底下。這個共用邏輯統一寫在 `_shared.py`（`SUMMARY_HOME_AREA = "台北"`），4 支功能檔案都從這裡拿 `open_area_summary()` / `open_area_folder()`，之後結構再變動只需要改一個地方。

UI 操作順序：**選擇地區（全部或單一） → 選擇年月 YYYYMM → 選擇功能**

四個功能：內勤結算 / 內勤PDF產出 / 內勤薪資單通知信 / 內勤元大帳戶

### 1. 內勤結算（`settlement.py`）— 已完成

根目錄》YYYY薪資》台北資料夾》YYYY地區薪資單總表》薪資單工作表

1. `AC1` 寫入 `YYYY.MM`
2. 清空 `C3:D`
3. 讀「員工個資」工作表 J欄=='Y' 的姓名 → 寫入「薪資單」`B3:B`，對應列 `D3:D` 設為 `TRUE`

### 2. 內勤PDF產出（`pdf_export.py`）— 已完成

- 與清潔承攬/其他承攬的 PDF 產出機制**各自獨立**，互不影響；也跟你截圖裡「D欄勾選→產生PDF」那支既有機制無關，不會重複處理
- 只處理薪資單分頁 `B3:B` 名單裡 **`D` 欄為 `TRUE`** 的人（尊重手動取消勾選，不是整批 `B3:B` 都出），逐一寫入 `AC2`，短暫等待公式重算後，用 Sheets export 端點只匯出 `AA1:AH15` 這個範圍成 PDF
- 檔名：`YYYYMM地區薪資單_姓名.pdf`（如 `202601台北薪資單_賴彥妃.pdf`）
- 存到 `根目錄》YYYY》地區》薪資單` 資料夾（這個子資料夾還是各地區自己的，沒有跟著總表搬去台北），連結寫回「薪資單」`C` 欄對應列：
  - `C` 欄該列原本是空的 → 上傳新檔（同名先丟垃圾桶再上傳，避免疊加），把新連結寫回 `C`
  - `C` 欄該列已經有連結 → 沿用連結對應的原檔案直接覆蓋內容（不新建檔案），重新產出後連結網址不變，之前分享出去的連結還是打得開

### 3. 內勤薪資單通知信（`mail_notify.py`）— 已完成

根目錄》YYYY薪資》YYYY內勤薪資名冊，兩個工作表：

**`mail` 工作表**（實際截圖確認：只有 A 欄 name、B 欄 mail 兩欄）：
1. A2:An：依序把台北→桃園「員工個資 J欄=='Y'」的內勤員工姓名接起來（沿用「薪資單」B3:B，內勤結算跑完後已經是篩選過的名單）
2. B2:Bn：mail 工作表 A欄（姓名）＝該地區「員工個資」B欄時，對應的員工個資 **F欄**（信箱來源是員工個資，不是薪資單自己的欄位，2026-08-20 確認）

**當月 `YYYYMM` 工作表**：
1. 複製「名冊」裡**最近一個月**的分頁（不是固定樣板）→ 改名成當月 YYYYMM → 刪除新分頁的 F 欄（避免上個月的寄信狀態帶到新月份）→ 把新分頁的 **D1**（不是整個 D 欄）改成當月 YYYYMM → **清空 B2:C**（複製過來的上個月姓名/連結要清掉，等重新填當月名單）。第一次建立、前一個月分頁還不存在時會丟出清楚的錯誤訊息，請先手動建立第一份月份分頁範本。
2. B2 起依序貼台北「薪資單」B3:B（姓名）、C3:C（連結），同一批列的 **D 欄寫入「台北」**
3. 桃園緊接在台北最後一列之後（動態接續、不是固定位置），同一批列的 **D 欄寫入「桃園」**

已確認的名單邏輯：只看「員工個資」J欄是否為 Y（在職/適用旗標），不是看薪資單 D3:D 當月是否勾選發薪；這支程式只整理名冊/收件清單，不寄信，寄信是另一套機制觸發，跟這支程式無關。

**尚未驗證的假設：** 「薪資單」C3:C（連結）目前沒有其他程式會寫入，這裡假設是既有維護在該工作表上的資料；如果實際欄位不是這樣，調整 `mail_notify._read_payroll_names_and_links()` 的欄位索引即可。

### 4. 內勤元大帳戶（`yuanta_account.py`）— 已完成

根目錄》YYYY薪資》台北資料夾》YYYY元大帳戶-地區

**元大工作表實際欄位**（2026-08-20 用實際截圖確認：row1 是「所有欄位請勿自行新增或刪除」提示列，row2 是表頭，資料從 row3 開始）：

| 欄 | 表頭 | 內容 |
|---|---|---|
| A | 轉帳日期(yyyymmdd) | 下個月的 5 日，遇六日往前挪到最近工作日 |
| B | 受款人身分證字號 | 對到台北「員工個資」B欄=姓名 時的 C欄 |
| C | 受款人帳號 | 對到台北「員工個資」B欄=姓名 時的 I欄 |
| D | 金額 | 對到台北「薪資單」D欄=姓名 且 A欄=YYYY.MM 時的 AH欄 |
| E | 員工姓名 | 該地區自己「薪資單」B3:B |

**2026-08-20 已確認的重點：E 欄（姓名清單）用地區自己的薪資單，但 B/C/D 三欄的查找一律固定查「台北」那份總表**，不是查地區自己的——元大帳戶用的員工銀行資料／金額主表只在台北那份總表裡。`run_yuanta_account()` 已依此實作：`own_summary`（地區自己，只用來抓 E 欄姓名）跟 `taipei_summary`（固定台北，B/C/D 三欄查找都用它）分開開兩份試算表。

其他步驟：
- **K2** 寫入 YYYY.MM；寫完後檢查 **F3:F**，若有任何非 0（或無法判讀成數字）的值，回傳結果會帶 `warning` 欄位，toolapp.py 會在執行日誌用 ⚠️ 提醒使用者人工確認（不清楚 F 欄實際公式在算什麼，只按規格做「非 0 就提醒」）
- 另存 `YYYYMM元大帳戶-地區.xlsx`，存回跟元大帳戶試算表同一個 Drive 資料夾（同名先丟垃圾桶再上傳）

**尚未驗證的假設：**
- 「元大工作表」規格沒指名分頁名稱，`_get_yuanta_ws()` 假設是該試算表的**預設（第一個）工作表**
- 步驟4「薪資單 D欄=姓名 且 A欄=YYYY.MM 時的 AH欄」照字面直接對「薪資單」工作表整份資料的 A/D/AH 欄做比對（不是走 AC1/AC2 那組單人樣板的公式重算）——2026-08-20 你貼的截圖顯示這份月份×員工的紀錄表確實是 A=月份(2026.08 這種格式)、D=姓名、AH=實領薪資金額，跟原本假設一致，算是驗證過了
- A3:A 的「例假日」只避開週末，沒有國定假日資料來源，遇到連假還是要人工核對

## 已知風險 / 建議下一步

上面各節「尚未驗證的假設」目前無法在這個環境對照到真實 Google Sheet 逐一驗證，建議：

1. 先在測試用的年月／地區跑一次，人工核對 mail 分頁、當月分頁、元大帳戶分頁的內容
2. 元大帳戶特別要核對受款人身分證字號／帳號／金額有沒有對到正確的人，這份是實際轉帳用的檔案，錯了風險比較高
3. 如果欄位對應不對，只要調整對應檔案裡的欄位索引常數即可，不用改架構
